# 07. n8n Workflow C — статусы PM и завершение (Asana → Rocket.Chat)

Этот workflow закрывает “петлю прозрачности” для инициатора:

- PM принял решение (Approved / Need info / Rejected) → инициатор видит статус в треде Rocket.Chat
- задача завершена (`Done`) → инициатор получает “готово” в треде

Важно: это **не меняет роли**. PM по‑прежнему принимает решения в Asana. Интеграция лишь публикует уведомления.

---

## 1) Два способа реализации (выберите один)

### Вариант 1 (рекомендуемо): Asana Webhooks (почти в реальном времени)
Плюсы:

- сообщения отправляются сразу после изменения
- меньше “пустых” проверок

Минусы:

- нужна настройка webhooks (и разовая “подписка”)
- в некоторых окружениях надо аккуратно пройти handshake (подтверждение вебхука)

### Вариант 2 (проще): Polling по cron (периодическая проверка)
Плюсы:

- не нужен webhook handshake
- часто проще для пилота

Минусы:

- задержка (например, до 1 часа)
- нужно хранить “предыдущее состояние”, чтобы не слать повторно

Далее описаны оба. На пилоте можно начать с polling, затем перейти на webhooks.

---

## 2) Что нужно в данных

Чтобы отправить сообщение “в нужный тред”, workflow должен знать:

- `rc_room_id`
- `rc_thread_id`

Они сохраняются при intake в Data Store `asana_to_rc` (см. `05_workflow_A_intake.md` и `04_n8n_setup.md`).

---

## 3) Какие события публикуем в Rocket.Chat

Минимальный набор:

- **Approved**: “PM подтвердил задачу, можно выполнять: <asana_link>”
- **Need info**: “Нужны уточнения: <вопрос(ы)>”
- **Rejected**: “Запрос отклонён: <причина>”
- **Done**: “Готово: <asana_link>”

Шаблоны — `09_message_templates.md`.

Рекомендация для “Need info/Rejected”: чтобы сообщение было полезным, договоритесь, что PM пишет **комментарий** в Asana с префиксом:

- `Вопрос инициатору:` … (для Need info)
- `Причина отказа:` … (для Rejected)

Workflow берёт последний такой комментарий и вставляет в сообщение (если это реализуемо в вашей версии без усложнений).

## 4) Вариант 1: Webhooks (Asana → n8n)

### 4.1 Создайте workflow
Название: **Workflow C — Asana webhook → Rocket.Chat status**

### 4.2 Webhook Trigger (вход от Asana)
Создайте Webhook node:

- Method: POST
- Path: например `/asana-events`

### 4.3 Handshake Asana webhook (важный момент)
Asana при создании webhook делает “проверочный запрос” и ожидает, что ваш endpoint вернёт заголовок `X-Hook-Secret`.

Что сделать:

- проверьте, что n8n может ответить нужным заголовком (через настройку Webhook response / Respond to Webhook node)
- если не получается — используйте polling вариант (ниже) или обратитесь к администратору n8n/инфры

### 4.4 Подпишитесь на события проекта Inbox
Asana webhooks обычно создаются через API (создать подписку на ресурс).

Практический подход “без кода”:

- в n8n создайте **одноразовый** workflow “Create webhook subscription”, который вызовет Asana API “Create webhook”
- в качестве `target` укажите URL вашего `/asana-events`
- в качестве `resource` укажите `project_gid` Inbox

После успеха — этот одноразовый workflow можно выключить.

### 4.5 Обработка события
Asana обычно присылает только “событие изменилось”, без деталей. Поэтому типовой шаг:

1) получить `task_gid` из события
2) сделать Asana API “Get task details” (нужные поля)
3) решить, нужно ли отправлять сообщение

### 4.6 Решение “что отправлять”

#### A) Завершение
Если `completed=true`:

- проверьте Data Store `completion_notified` по `task_gid`
- если ещё не отправляли:
  - найдите `rc_room_id/rc_thread_id` через `asana_to_rc`
  - отправьте “Done” в тред
  - запишите `completion_notified`

#### B) Решение PM (если используете поле `PM Decision`)
Если поле `PM Decision` изменилось на:

- `Need info` → отправить “нужны уточнения”
- `Rejected` → отправить “отклонено”
- `Approved` → (опционально) отправить “подтверждено”

Чтобы сообщение было полезным, можно подтянуть последний комментарий и вставить вопрос/причину (по префиксам из раздела 3).

## 5) Вариант 2: Polling (Cron → Asana → Rocket.Chat)

### 5.1 Создайте workflow
Название: **Workflow C — Polling status/completion**

### 5.2 Cron Trigger
Рекомендуемо: 30–60 минут.

### 5.3 Получите список задач Source=Rocket.Chat
Два запроса:

- активные (не completed) — чтобы проверять `PM Decision`
- завершённые (completed) — чтобы отправлять “Done” один раз

Если поиск “completed tasks” неудобен в вашей поставке Asana, используйте альтернативу:

- храните список `asana_task_gid` из `asana_to_rc` и периодически проверяйте их статус по одному  
  (это проще логически, но больше запросов)

### 5.4 Anti‑spam
Используйте:

- `completion_notified` для “Done”
- отдельный store (например, `status_notified`) для решений PM, чтобы не повторять одно и то же

---

## 6) Тест‑чек‑лист workflow C

1) Создайте задачу из Rocket.Chat (workflow A).
2) В Asana поменяйте `PM Decision` на `Need info` и добавьте комментарий “Вопрос инициатору: …” → в тред должен прийти запрос уточнений.
3) Поменяйте на `Approved` → (если включили) в тред должно прийти подтверждение.
4) Поменяйте на `Rejected` + комментарий “Причина отказа: …” → в тред должна прийти причина.
5) Переведите задачу в `Done` → инициатор должен получить “Готово”.
6) Убедитесь, что повторные изменения/запуски **не** дублируют “Done”.
