# Implementation guide: Rocket.Chat ↔ Asana (Asana-native + Teammates) — пошаговое внедрение

Этот набор документов описывает, **как внедрить** решение из `solution_nocode_teammate.md`:

- Пользовательские интерфейсы: **только Rocket.Chat и Asana**
- Роли: **Инициатор / PM / Исполнитель** (без изменения ответственности)
- “Интеллект”: **Asana Intelligence / AI Teammates** (human‑in‑the‑loop)
- Интеграция “под капотом” (без UI): **n8n** (webhooks + API вызовы)

Документы написаны так, чтобы инженер‑внедренец мог сделать настройку **без программирования**, имея базовый опыт работы с корпоративными системами.

---

## Что получится в итоге (критерии готовности)

Считаем внедрение успешным, когда выполняется следующее:

### A) Для одного запроса (end‑to‑end)
- Инициатор пишет сообщение в `#task-requests` (или выбранный канал).
- В Asana автоматически появляется **ровно одна** задача в проекте “Inbox from Rocket.Chat” со связью с тредом Rocket.Chat (ссылка + IDs).
- В треде Rocket.Chat появляется ответ бота “Черновик задачи создан: <ссылка>”.
- PM в Asana подтверждает/правит критические поля (срок/исполнитель/приоритет) и при необходимости задаёт уточняющие вопросы инициатору через тред.

### B) Для контроля выполнения
- PM получает **минимум шума**: ежедневный обзор делает в Asana; в Rocket.Chat приходят только “красные” уведомления.
- Нет дублей: повторное сообщение/ивент из Rocket.Chat **не создаёт** новую задачу (идемпотентность).
- При переводе задачи в `Done` инициатор получает уведомление “готово” в треде.

## Рекомендованный порядок работ (время — ориентировочно)

- **Подготовка (0.5–2 часа)**: согласовать канал/проекты, права, пороги X/Y, правила уведомлений.
- **Asana (1–2 часа)**: проект Inbox, поля, базовый процесс и “definition of done”.
- **Rocket.Chat (0.5–1.5 часа)**: канал, бот/токен, outgoing webhook.
- **n8n (2–6 часов)**: развернуть, подключить креды, собрать 2 workflow, включить дедуп/кулдауны.
- **Тест/пилот (1–3 часа + 2–5 дней наблюдения)**: тестовые кейсы, настройка порогов/шума.
