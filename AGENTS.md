# AGENTS.md

Этот репозиторий — **документация** (Markdown) по решению и пошаговому внедрению интеграции **Rocket.Chat ↔ Asana** с “интеллектом” на стороне **Asana Intelligence / AI Teammates** и интеграционным слоем **n8n** (без нового пользовательского UI).

Ниже — правила и ориентиры для AI-агентов/контрибьюторов, которые вносят изменения в эти материалы.

### Цель агента в этом репозитории

- **Поддерживать единый, применимый на практике набор документов**, по которым инженер‑внедренец может повторить настройку “как есть”.
- **Не придумывать продуктовые возможности** Rocket.Chat/Asana/n8n “из головы”: если функция спорная — помечать как допущение или давать альтернативу.
- **Сохранять human‑in‑the‑loop**: AI предлагает и анализирует, решения принимает человек (PM).

### Где что лежит (канонические документы)

- **`README.md` (root)**: краткое описание репозитория (одна строка/аннотация).
- **`product_story.md`**: продающее повествование/ценность для ролей (инициатор/PM/исполнитель).
- **`solution_nocode_teammate.md`**: архитектура и “Asana‑native” концепция решения (без кода).
- **`implementation/README.md`**: критерии готовности + оглавление и порядок внедрения.
- **`implementation/01_prerequisites_and_decisions.md`**: доступы, лицензии, решения “до старта”, словарь/схема данных.
- **`implementation/02_asana_setup.md`**: настройка Asana (проект Inbox, поля, правила, Teammates).
- **`implementation/03_rocketchat_setup.md`**: настройка Rocket.Chat (каналы/бот/Outgoing Webhook/права).
- **`implementation/04_n8n_setup.md`**: размещение и базовая эксплуатация n8n (security/creds/datastore/observability).
- **`implementation/05_workflow_A_intake.md`**: workflow “Intake” (Rocket.Chat → Asana → Rocket.Chat).
- **`implementation/06_workflow_B_red_alerts.md`**: workflow “Red alerts” (Cron → Asana → правила риска → Rocket.Chat).
- **`implementation/07_workflow_C_status_and_completion.md`**: статусы/вебхуки Asana → уведомления Rocket.Chat.
- **`implementation/08_operations_testing_rollout.md`**: тест‑план, пилот, запуск, troubleshooting, rollback.
- **`implementation/09_message_templates.md`**: шаблоны сообщений (anti‑spam).

### Рабочие правила (как вносить правки)

- **Пиши правду и проверяемое**: если точная настройка/лимит/название пункта меню может отличаться по версии, укажи это (“может называться иначе”, “проверьте в Admin UI”) и добавь понятный fallback.
- **Не добавляй “реализацию в коде”**: этот репозиторий про внедрение без программирования. Допустимы только:
  - краткие псевдошаги;
  - примеры payload/полей;
  - конфигурационные рекомендации.
- **Держи связность**:
  - если меняешь процесс — синхронизируй `solution_nocode_teammate.md` и соответствующий файл в `implementation/`;
  - если меняются критерии готовности/Definition of Done — обнови `implementation/README.md`.
- **Не ломай терминологию**: роли **Инициатор / PM / Исполнитель**, “Inbox from Rocket.Chat”, “Intake / Red alerts / Status & completion”, “идемпотентность / дедуп / кулдауны / anti‑spam”.
- **Сохраняй минимализм**: интеграция — “тонкий мост”, логика контроля — максимально простые проверяемые сигналы.

### Инварианты решения (не нарушать без явного запроса)

- **Один запрос → одна задача**: обязателен дедуп по устойчивому ключу (например, `message_id + thread_id`), без дублей.
- **Anti‑spam по умолчанию**: уведомления в Rocket.Chat только по “красным” событиям и по кулдаунам.
- **Трассируемость**: задача в Asana должна содержать связь с исходным тредом Rocket.Chat (ссылка + IDs/метаданные).
- **Human-in-the-loop**: критические поля (срок/исполнитель/приоритет) считаются подтверждёнными только после решения PM.

### Стиль и формат Markdown

- **Язык**: основной — русский (как в текущих документах). Английские термины допустимы для названий продуктов/фич.
- **Структура**: короткие разделы, списки, чек‑листы; избегай “простыней”.
- **Ссылки**: если добавляешь внешние ссылки — предпочитай официальные материалы вендоров; не вставляй “голые” URL в тексте без контекста.
- **Шаблоны сообщений**: тексты должны быть короткими, нейтральными, без спама; учитывай, что сообщения читаются в тредах.

### Быстрый чек‑лист перед завершением задачи

- **Правки сделаны в правильном файле** (story vs solution vs implementation).
- **Кросс‑ссылки не устарели** (упоминания файлов/шагов совпадают с оглавлением `implementation/README.md`).
- **Критерии готовности не расходятся** с описанным процессом.
- **Idempotency / anti‑spam / трассируемость / human‑in‑the‑loop** сохранены или явно обоснованно изменены.
