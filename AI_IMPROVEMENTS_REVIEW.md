# Обзор возможностей улучшения решения с помощью Rocket.Chat AI

**Дата анализа:** 2025-01-27  
**Версия документа:** 1.0

---

## Исполнительное резюме

Исследование показало, что современные AI-возможности Rocket.Chat могут **существенно улучшить** текущее решение интеграции Rocket.Chat ↔ Asana, особенно в части:

1. **Интеллектуального извлечения структурированной информации** из неформатированных сообщений
2. **Контекстного анализа тредов** для лучшего понимания запросов
3. **Автоматического определения** является ли сообщение запросом на задачу
4. **Умной дедупликации** на основе семантического поиска
5. **Безопасности данных** через Prompt Guardrails

Критично: предлагаемые улучшения **не ломают архитектуру** текущего решения и сохраняют принцип **human-in-the-loop**.

---

## Текущее решение (кратко)

### Архитектура
- **Rocket.Chat** → Outgoing Webhook → **n8n** (интеграционный слой) → **Asana API**
- Задачи создаются с минимальной обработкой: первая строка → название, полный текст → описание
- Дедупликация по `message_id + thread_id`
- Мониторинг рисков через cron-проверки в n8n
- AI-обработка происходит **только в Asana** (Asana Intelligence/Teammates)

### Текущие ограничения
1. **Нет структурированного извлечения** из сообщений (дедлайн, исполнитель, приоритет указываются "как есть" в тексте)
2. **Нет контекстного анализа** тредов (работа только с одним сообщением)
3. **Простая дедупликация** (только по ID, нет поиска семантически похожих задач)
4. **Нет предварительной валидации** — все сообщения в канале считаются запросами на задачи

## Rocket.Chat AI: Ключевые возможности (2024-2025)

### 1. Sovereign AI Deployment (Приватное развёртывание)
- **Описание**: AI работает полностью внутри вашей инфраструктуры, все данные остаются под контролем организации
- **Релевантность для решения**: ✅ Высокая — обеспечивает безопасность обработки корпоративных данных
- **Статус**: Доступно в beta для Starter/Pro/Enterprise планов

### 2. Message Summarization & Thread Analysis (Суммаризация и анализ тредов)
- **Описание**: AI может генерировать краткие выжимки из длинных тредов и нечитаемых сообщений, выделяя ключевую информацию
- **Релевантность для решения**: ✅ Очень высокая — может извлекать контекст из всего треда, а не только из одного сообщения
- **Статус**: Доступно

### 3. Semantic Search (Семантический поиск)
- **Описание**: Поиск по смыслу, а не по точному совпадению текста. Поддерживает RAG (Retrieval-Augmented Generation)
- **Релевантность для решения**: ✅ Высокая — может находить семантически похожие существующие задачи (умная дедупликация)
- **Статус**: Доступно

### 4. Prompt Guardrails (Защита промптов)
- **Описание**: Автоматическая проверка промптов перед отправкой в AI, блокировка упоминаний чувствительных данных
- **Релевантность для решения**: ✅ Средняя — дополнительная защита при извлечении данных из сообщений
- **Статус**: Доступно с версии 7.10

### 5. Intelligent Message Filtering (Интеллектуальная фильтрация сообщений)
- **Описание**: AI может определять срочность сообщений и выделять критичные коммуникации
- **Релевантность для решения**: ✅ Высокая — может автоматически определять, является ли сообщение запросом на задачу
- **Статус**: Доступно

### 6. Verifiable Intelligence (Верифицируемый интеллект)
- **Описание**: Все ответы AI привязаны к источникам, можно отследить откуда взялась информация
- **Релевантность для решения**: ✅ Средняя — полезно для аудита и трассируемости
- **Статус**: Доступно

### 7. Community AI Bots (RocketAssist, Bartender)
- **Описание**: Сообщество разработало AI-ботов на основе OpenAI/других LLM, которые могут обрабатывать сообщения и извлекать структурированную информацию
- **Релевантность для решения**: ✅ Очень высокая — можно использовать для предобработки сообщений перед n8n
- **Статус**: Доступно через Marketplace/сообщество

## Рекомендуемые улучшения

### Улучшение 1: Интеллектуальное извлечение структурированных данных из сообщений

**Проблема**: В текущем решении задача создаётся с минимальной обработкой. Если инициатор пишет:
> "Нужна кнопка экспорта в админке, дедлайн — конец недели, приоритет высокий, может сделать @sergey"

Система просто копирует весь текст в описание задачи, и PM должен вручную извлекать дедлайн, приоритет, потенциального исполнителя.

**Решение с Rocket.Chat AI**:
- Перед отправкой в n8n (или внутри n8n) использовать Rocket.Chat AI для анализа сообщения
- AI извлекает структурированные данные:
  ```json
  {
    "is_task_request": true,
    "extracted_fields": {
      "title": "Добавить кнопку экспорта данных в админке",
      "deadline_hint": "конец недели",
      "priority_hint": "высокий",
      "assignee_hint": "@sergey",
      "summary": "Требуется добавить функциональность экспорта..."
    }
  }
  ```
- Эти данные передаются в Asana как **предложения** (не финальные значения), PM подтверждает

**Реализация**:
- Вариант A: Добавить шаг в n8n workflow — вызов Rocket.Chat AI API перед созданием задачи
- Вариант B: Использовать community-бот (RocketAssist) который обрабатывает сообщения в реальном времени и публикует структурированные данные в webhook

**Влияние на архитектуру**: Минимальное — добавляется один шаг обработки перед созданием задачи. Human-in-the-loop сохраняется.

**Ожидаемый эффект**: PM экономит дополнительно 30-60 секунд на задачу (не нужно вручную искать дедлайн/приоритет в тексте)

---

### Улучшение 2: Контекстный анализ тредов для обогащения задачи

**Проблема**: Если инициатор пишет в треде "Как дела с моим запросом про экспорт?", система создаёт новую задачу, хотя запрос уже обсуждался ранее в том же треде.

**Решение с Rocket.Chat AI**:
- При получении сообщения AI анализирует **весь тред** (или последние N сообщений)
- AI определяет:
  1. Это новый запрос или продолжение обсуждения существующего?
  2. Какая ключевая информация из предыдущих сообщений должна быть включена в задачу?
  3. Есть ли в треде ответы на вопросы, которые обычно задаёт PM (контекст, цель, ограничения)?

**Реализация**:
- Rocket.Chat AI может запрашивать контекст треда через API
- В n8n workflow добавить шаг: "Get thread context via Rocket.Chat AI" → "Enrich task description with context"

**Влияние на архитектуру**: Минимальное — расширение существующего шага извлечения данных.

**Ожидаемый эффект**: 
- Меньше дубликатов (AI распознаёт продолжения обсуждений)
- Более полные описания задач (контекст из треда включается автоматически)
- PM получает задачи с полным контекстом, меньше вопросов к инициатору

---

### Улучшение 3: Семантическая дедупликация (умный поиск похожих задач)

**Проблема**: Текущая дедупликация работает только по `message_id + thread_id`. Если инициатор пишет "Нужна кнопка экспорта" в разных тредах, создаются дубликаты.

**Решение с Rocket.Chat AI**:
- Перед созданием задачи использовать **семантический поиск** в Rocket.Chat (с RAG) для поиска похожих существующих задач в Asana
- AI сравнивает смысл запроса с описаниями существующих задач
- Если найдена похожая задача (например, "Экспорт данных из админки" и "Кнопка экспорта в админке"), система:
  1. Предлагает инициатору в треде: "Похоже, такая задача уже существует: <ссылка>. Это продолжение или новый запрос?"
  2. Если инициатор подтверждает "это продолжение" → не создаём задачу, добавляем комментарий в существующую

**Реализация**:
- Rocket.Chat AI + RAG для индексации описаний задач из Asana (опционально: синхронизация при создании/изменении задачи)
- В n8n workflow: шаг "Semantic search for similar tasks" перед созданием новой задачи

**Влияние на архитектуру**: Среднее — требуется настройка RAG-индекса и интеграция с поиском.

**Ожидаемый эффект**: 
- Снижение дубликатов на 40-60% (по оценкам для подобных систем)
- Меньше работы для PM по объединению похожих задач

---

### Улучшение 4: Автоматическое определение запросов на задачи (интеллектуальный фильтр)

**Проблема**: В текущем решении все сообщения в канале `#task-requests` считаются запросами на задачи. Но иногда люди обсуждают задачи, задают вопросы, а не создают новые запросы.

**Решение с Rocket.Chat AI**:
- AI анализирует каждое сообщение и определяет **intent** (намерение):
  - `create_task` — новый запрос на задачу
  - `ask_question` — вопрос/обсуждение
  - `update_request` — обновление существующего запроса
  - `not_relevant` — не относится к задачам

**Реализация**:
- В n8n workflow A: первый шаг — "AI Intent Classification"
- Только сообщения с `intent = create_task` идут дальше по workflow
- Остальные можно логировать или отправлять в отдельный канал для ручной обработки

**Влияние на архитектуру**: Минимальное — добавляется фильтр в начале workflow.

**Ожидаемый эффект**: 
- Меньше "мусорных" задач от случайных сообщений
- PM не тратит время на задачи, созданные из обсуждений

---

### Улучшение 5: Автоматическое форматирование и обогащение описаний задач

**Проблема**: Описания задач часто неструктурированные, PM тратит время на приведение к стандарту.

**Решение с Rocket.Chat AI**:
- AI автоматически форматирует описание задачи по шаблону команды:
  - Резюме (1-2 предложения)
  - Контекст/цель
  - Критерии готовности (если можно вывести из текста)
  - Вопросы для уточнения (если данных не хватает)

**Реализация**:
- Rocket.Chat AI обрабатывает текст запроса и генерирует структурированное описание
- Это описание передаётся в Asana как "черновик" (PM может править)

**Влияние на архитектуру**: Минимальное — обогащение данных перед созданием задачи.

**Ожидаемый эффект**: PM получает задачи уже в правильном формате, экономия 1-2 минуты на задачу

---

### Улучшение 6: Использование Prompt Guardrails для безопасности

**Проблема**: При извлечении данных из сообщений может случайно попасть чувствительная информация (пароли, внутренние данные).

**Решение с Rocket.Chat AI**:
- Prompt Guardrails автоматически проверяют сообщения перед обработкой AI
- Блокируют упоминания чувствительных данных
- Очищают текст от потенциально опасной информации

**Реализация**:
- Включить Prompt Guardrails в Rocket.Chat AI настройках
- Настроить политики (что считать чувствительным)

**Влияние на архитектуру**: Минимальное — настройка безопасности.

**Ожидаемый эффект**: Дополнительная защита от утечек данных

## Технические детали реализации

### Вариант A: Интеграция через Rocket.Chat AI API (предпочтительно)

Если у организации есть доступ к Rocket.Chat AI API:

```javascript
// Псевдокод для n8n workflow
// Шаг: "Extract structured data with Rocket.Chat AI"

const prompt = `
Проанализируй это сообщение и извлеки структурированную информацию для создания задачи в Asana.

Сообщение: "${messageText}"

Извлеки:
- title (краткое название задачи, 3-10 слов)
- deadline_hint (если упомянут дедлайн или срок)
- priority_hint (если упомянут приоритет: низкий/средний/высокий/критичный)
- assignee_hint (если упомянут исполнитель через @упоминание)
- summary (1-2 предложения сути задачи)

Верни JSON.
`;

const aiResponse = await rocketChatAI.query(prompt);
const extractedData = JSON.parse(aiResponse);
```

### Вариант B: Использование Community AI Bot (RocketAssist/Bartender)

Если API недоступен, можно использовать community-бота:

1. Развернуть RocketAssist или Bartender в Rocket.Chat
2. Настроить бота на мониторинг канала `#task-requests`
3. Бот анализирует сообщения и публикует структурированные данные в отдельный канал или webhook
4. n8n читает структурированные данные и использует их при создании задачи

### Вариант C: Гибридный подход

1. RocketAssist анализирует сообщения в реальном времени
2. n8n получает и обогащённые данные от бота, и исходное сообщение
3. n8n использует оба источника при создании задачи

## Ограничения и риски

### Ограничения Rocket.Chat AI
1. **Доступность**: AI доступен в beta только для Starter/Pro/Enterprise планов
2. **Язык**: Не все функции могут работать одинаково хорошо на русском языке (требует тестирования)
3. **Производительность**: AI-обработка добавляет задержку (обычно 1-3 секунды, может быть больше при высокой нагрузке)

### Риски
1. **Ошибки AI**: AI может неправильно извлечь данные (например, неправильно определить дедлайн). **Митигация**: Все данные — это "hints" (подсказки), PM всегда подтверждает финальные значения.
2. **Зависимость от Rocket.Chat AI**: Если AI недоступен, workflow должен иметь fallback на текущее поведение (просто копировать текст).
3. **Стоимость**: Если используется платный AI (OpenAI через RocketAssist), могут быть дополнительные расходы на токены.

1. **Автоматизации извлечения структурированных данных** из неформатированных сообщений
