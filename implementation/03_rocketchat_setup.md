# 03. Настройка Rocket.Chat (каналы, бот, Outgoing Webhook)

Цель: сделать так, чтобы Rocket.Chat автоматически отправлял событие о новом сообщении в канале запросов в n8n, а бот мог отвечать в тред ссылкой на задачу Asana и присылать уведомления PM.  
Дополнительно (по условиям внедрения): включить **Rocket.Chat AI** так, чтобы он улучшал Intake “под капотом” (intent/extraction/thread summary/семантические подсказки) и не создавал нового пользовательского UI.

---

## 1) Подготовка

Вам понадобятся:

- права администратора Rocket.Chat (или роль с доступом к Integrations/Webhooks)
- решение из `01_prerequisites_and_decisions.md`:
  - канал запросов (например, `#task-requests`)
  - канал для PM‑алертов (например, `#pm-alerts`)
- доступ к **Rocket.Chat AI** и **Rocket.Chat AI API** (если в вашей поставке включается отдельно)

---

## 2) Создайте/проверьте канал запросов

1) Создайте публичный или приватный канал `#task-requests`.
2) Убедитесь, что в канале разрешены треды (обычно включены по умолчанию).
3) Добавьте в канал:
   - всех инициаторов (кто будет писать запросы)
   - PM(ов)
   - (опционально) наблюдателей/лидов

Рекомендация: попросите команду писать запросы **в одном канале**, чтобы интеграция была максимально простой.

---

## 3) Создайте сервисного пользователя/бота

Задача бота:

- писать ответы в тред “Черновик задачи создан…”
- писать уведомления PM в `#pm-alerts` (только “красные”)

### Шаги
1) Создайте пользователя, например `asana-bot`.
2) Назначьте ему минимальные права:
   - читать/писать в `#task-requests` (чтобы отвечать в треды)
   - писать в `#pm-alerts`
3) Отключите для бота лишние возможности (если применимо):
   - запретить вход/2FA не требуется, если используете токен

### Получите токен для REST API
В зависимости от настроек Rocket.Chat это может быть:

- Personal Access Token (рекомендуемо)
- или пара `authToken` + `userId` для API

Сохраните токен в безопасном месте — он понадобится в `04_n8n_setup.md`.

---

## 3.1) Включите Rocket.Chat AI и Guardrails (рекомендуемо)

Важно: названия пунктов UI могут отличаться по версии/поставке. Ориентируйтесь на смысл: **включить AI**, **включить политики безопасности**, **разрешить API‑доступ**.

### Цель настройки
- AI доступен для вызова из n8n через Rocket.Chat AI API (без нового UI для пользователей).
- Включены **Prompt Guardrails** (или эквивалент): чтобы в AI‑обработку не попадали секреты/ключи/пароли, и чтобы AI‑ответы были безопасны для публикации.

### Практические шаги (общая логика)
1) В Admin UI Rocket.Chat найдите раздел AI / Rocket.Chat AI (или Apps → Rocket.Chat AI).
2) Включите модуль AI и проверьте, что он “Ready/Running”.
3) Включите Prompt Guardrails / policy checks (если доступно):
   - запрет/маскирование токенов, паролей, ключей
   - (опционально) классификация данных/доступов (RBAC)
4) Убедитесь, что AI API доступен из сети, где работает n8n (см. `04_n8n_setup.md`).

Примечание: если в вашей поставке Rocket.Chat AI развёрнут “суверенно” (внутри инфраструктуры) — это предпочтительно и снижает риск утечек.

---

## 3.2) (Опционально) Сервисный доступ для Rocket.Chat AI API

Если в вашей поставке для вызовов Rocket.Chat AI API нужен отдельный токен/роль:
- создайте отдельного технического пользователя (например, `rc-ai-service`)
- выдайте минимальные права для AI‑вызовов, которые нужны интеграции:
  - доступ к AI API
  - (если планируете суммаризацию треда “снаружи”) доступ на чтение сообщений в `#task-requests` и тредах
- сохраните токен как отдельные credentials в n8n (см. `04_n8n_setup.md`)

Если AI API использует те же механизмы авторизации, что и обычный Rocket.Chat REST API — можно использовать токен `asana-bot`, но лучше разделять сервисные доступы.

---

## 4) Настройте Outgoing Webhook (события → n8n)

### Что должно произойти
Когда кто-то пишет в `#task-requests`, Rocket.Chat отправляет HTTP POST на URL webhook‑триггера n8n (workflow A).

### Шаги в Rocket.Chat (общая логика)
1) Откройте **Administration → Integrations → New Integration → Outgoing Webhook** (названия могут отличаться по версии).
2) Заполните:
   - **Name**: `asana-intake`
   - **Channel**: `#task-requests` (строго один канал на старте)
   - **URLs**: URL webhook n8n из workflow A (см. `05_workflow_A_intake.md`)
   - **Token/Secret**: придумайте секрет (используется для проверки “это точно Rocket.Chat”)
3) Включите интеграцию и сохраните.

### Важные опции/фильтры (рекомендуемо)
Чтобы не создавать лишние задачи:

- Игнорировать сообщения от ботов/служебных пользователей (если есть такая настройка).
- Игнорировать правки/удаления сообщений (если Rocket.Chat отправляет и такие события).
- Триггерить только на новые сообщения.

---

## 5) Какие данные должны прийти в n8n

Payload зависит от версии Rocket.Chat, но вам критично получить:

- идентификатор сообщения: `message_id` (или `_id`)
- идентификатор канала/комнаты: `room_id` (или `rid`)
- текст сообщения: `text` (или `msg`)
- автора: `user` (или `u.username`)
- информацию о треде:
  - `thread_id` (или `tmid`/id корневого сообщения)

**Как проверить быстро:** отправьте тестовое сообщение в `#task-requests` и посмотрите в n8n “Execution data” у webhook‑триггера — там будет весь payload.

Дополнительно (для AI‑обогащения через контекст треда):
- возможность по `message_id/thread_id` получить последние N сообщений треда через Rocket.Chat REST API (интеграция сделает это в n8n)

---

## 6) Канал для PM‑уведомлений

1) Создайте канал `#pm-alerts` (желательно приватный).
2) Добавьте туда PM(ов) и `asana-bot`.
3) Правило: туда идут только “красные” уведомления и сообщения об ошибках интеграции.

---

## 7) Мини‑чек‑лист готовности Rocket.Chat

- [ ] Канал `#task-requests` существует и используется командой
- [ ] Канал `#pm-alerts` существует и доступен PM
- [ ] Сервисный пользователь/бот создан, у него есть токен
- [ ] Outgoing Webhook настроен на отправку в n8n webhook URL
- [ ] Тестовое сообщение из `#task-requests` доходит до n8n (видно в Execution data)
